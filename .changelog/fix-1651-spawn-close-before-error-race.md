- **`safeSpawnAsync` decides a never-started spawn from the `close` event's own shape, not from `error`'s arrival timing (refs #1651)** — the lifecycle-smoke lane's phase 5 pinned a genuinely-absent `gh` binary as classifying `missing` on Windows but `non-installable` on Linux CI. Root cause: Node's own docs leave the `error`/`close` event order unspecified for a child that never launched, and the real Linux shape closes such a child with a negative code (`-2` for ENOENT, `-4058` on Windows) — not the `null` this fix first assumed — with `error` sometimes landing a full tick later via `setImmediate`/`process.nextTick`, which a same-microtask identity re-check still loses against. `safeSpawnAsync`'s `close` handler now decides straight from `code === null || code < 0` — a shape no completed process ever produces — independent of whether or when `error` fires, reusing `error`'s Error when it's already available and synthesizing an ENOENT-shaped one otherwise. A single `resolved` flag, set by whichever handler decides first, stops the loser from ever overwriting an already-settled result — including the inverse case, where a healthy run (`close(0, null)`) must never be downgraded by a late, unrelated `error` (e.g. a post-exit `kill()` failing with `EPERM`). `classifyGhTokenFailure` in `clients/zizmor-config.ts` also gets a belt: it no longer trusts a bare `!res.error` as proof `gh` ran and answered — a `null`/negative `status` alone (OS-independent, read off Node's own report) now routes through the same missing/transient handling regardless of whether `error` happened to be attached. The lifecycle-smoke lane's phase 5 assertion (`outcome === "missing"`) was already the justified verdict; it needed no change.
  - `clients/safe-spawn.ts` — the `close`/`error` handlers inside `safeSpawnAsync`.
  - `clients/zizmor-config.ts` — `classifyGhTokenFailure`'s `neverAnswered` guard.
  - `tests/clients/safe-spawn-close-before-error-race.test.ts` — regression tests for the `close(-2, null)`/`close(null, null)` shapes (with and without a delayed `error`) and the healthy-run non-inversion case, all proven red on the round-1 fix before this round's shape-based rewrite.
