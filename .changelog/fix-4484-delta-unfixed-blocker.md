- **A second write no longer clears an unfixed blocker (closes #4484)** — When a write left an earlier error in place (it edited another line, or the next turn edited the file again), pi-lens treated "nothing new" as fixed: the write said `✓ clean`, the `--lens-guard` commit gate opened, `lens_diagnostics source=session` and the widget showed no issues, and turn end reported the error as cleared. The error now stays blocking until a check of the file no longer finds it: the write says `🔴 Still unfixed: N blocker(s) reported earlier (L…)` instead of clean, the commit gate stays shut, turn end lists it as unresolved, and the session store and widget keep it. This also holds for linters whose ids are positions (helm-lint), where fixing one error renumbers the next, and for a script run without authorship that leaves the error in place. The error also stays blocking when the write did not touch its lines (tree-sitter and ast-grep check only the edited lines for new blockers), when the language server or linter failed, timed out or did not answer on that write, when a slow checker's re-check was still running, and for an unused declaration that blocked when it was new. A write that removes the error still reports it resolved. A slow checker's re-check that finds the error gone clears it, at the commit gate or at turn end; one that failed clears nothing.
