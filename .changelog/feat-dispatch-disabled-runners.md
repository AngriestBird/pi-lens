- **`dispatch.disabledRunners` turns a dispatch runner off** — list runner ids such as `["dotnet-build"]` in `~/.pi-lens/config.json` or a project `.pi-lens.json` and pi-lens never runs them, so no `dotnet build` (or other tool) is spawned while the language server and every other runner in the group keep working. The list is a denial, resolved like `lsp.disabledServers`: the union of every tier, so a project can add a runner but never re-enable one you denied. A disabled runner is recorded as skipped with the reason `disabled-by-config`, not as a failure, and a fallback group moves on to its next runner. A nested `.pi-lens.json` governs the files under it. When config denied every checker that could not answer, the coverage notice and status line name `dispatch.disabledRunners` once per session; when a sibling also failed, they name the failure and the denial together. An id that names no runner is dropped with a `PILENS_CFG_0005` warning that quotes it. `effective_config` shows the runner as `disabled-by-config` with the tier and file that denied it. `dispatch.runnerTimeoutFloorMs` stays global-only and a project file that sets it is now told so. `rules.<id>.disable`, `select` and `ignorePaths` now follow the same owner: each file reads them from the nearest `.pi-lens.json` at or above it, on every surface that filters by them (dispatch, `lens_diagnostics`, `lsp_diagnostics`, the turn-end advisories), and the root's policy still reaches nested files. A nested `ignorePaths` glob is relative to its own file's directory (refs #5010).
