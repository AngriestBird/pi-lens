section: Fixed
---

- **Idle-reset timer no longer destroys the LSP service mid-sweep (refs [#1618](https://github.com/apmantza/pi-lens/issues/1618))** — `handleTurnEnd` arms a detached 240s idle-reset timer on a file-less turn, but `lens_diagnostics mode=full` grants its own workspace sweep a 300s wall-clock ceiling — 60s longer than the timer that could destroy the very service the sweep was touching. A maintainer-supervised forensics pass on a 2026-08-18 sweep found the timer firing 2s before completion, mislabeling ~81 service-destroyed files as budget exhaustion. `clients/lsp/workspace-sweep-hold.ts` is a new counter-based hold: `runWorkspaceDiagnostics` acquires it for its whole call (try/finally, so a throw or an overlapping sweep still releases correctly) and the idle-reset timer defers instead of firing while any sweep holds it, re-arming a fresh delay once the last sweep releases. The base idle-reset delay is now derived from the sweep's own wall-clock ceiling plus a safety margin (360s given the 300s default), so the two constants can't drift back into this relationship.
- **`runWorkspaceDiagnostics` stops and marks the remainder on a destroyed service (refs [#1618](https://github.com/apmantza/pi-lens/issues/1618))** — `LSPWorkspaceDiagnosticResult` now carries a discriminated `unconfirmedReason` (`budget` / `inconclusive` / `coverage_gap` / `service_destroyed` / `error`) instead of one ambiguous `timedOut` flag. A service destroyed mid-sweep stops the loop for the remaining files (checked per group and per file, before any language-server round trip) and marks them `service_destroyed` — never a bare `timedOut` indistinguishable from a real budget timeout. `touchFile`'s destroyed early-return now emits a cheap, local `lsp_touch_file` record (`failureKind: "destroyed"`) instead of leaving zero trace.
- **`lens_diagnostics mode=full` renders the real unconfirmed reason (refs [#1618](https://github.com/apmantza/pi-lens/issues/1618))** — The `unconfirmedErrored = length - unconfirmedTimedOut` computation was structurally always 0 (the sweep's own catch block set both `error` and `timedOut`), so an errored file always rendered as "check didn't complete within budget." The note now tallies `unconfirmedReason` directly, so a service-destroyed or errored file reads honestly instead of as a budget timeout.
