section: Fixed
---

- **A lazy install that dies on a network blip is retried instead of skipped for the session (closes #1537)** — the "we already tried this" key went in BEFORE the install ran and never came out, so a `gem install rubocop` or `rustup component add rustfmt` that failed on a transient error was never attempted again, and the tool stayed silently skipped. The storm guard stays — these spawns are up to 3 minutes and both entry points are reached per save — but it now keys off the attempt's OUTCOME: a transient failure is retried after a cooldown (5 min, doubling, 30 min cap, at most 3 attempts before the verdict is terminal), while a durable one holds for the session. A missing package MANAGER is the durable case: no cooldown conjures a `gem`.
  - The two copies of that guard became one. `formatters.ts` carried its own `_lazyInstallAttempts` Set duplicating `lazy-installer.ts`'s, and a fix in one was not a fix. The state, the classification and the ladder now live in `lazy-installer.ts`; `formatters.ts` keeps only the part that is formatter business (a fresh binary on PATH invalidates every "not found" verdict). The merged seam also gains the session reset the runner copy never had, so a durable hold no longer outlives the session that justified it.
  - "We tried and the network failed" is now tellable from "this tool cannot be installed here". The lazy installers recorded nothing at all. Each attempt now produces an `InstallAttemptFact` in #1534's vocabulary, readable via `getLazyInstallAttempt` and consumable by `describeInstallAttempt` for the `availability_decision` install evidence, plus one `install`-subsystem log line per suppression carrying the cause, the attempt count and the remaining cooldown.
