section: Fixed

- **TypeScript pull-settle records now report a real settle duration, a real version, and a distinct source (refs #1639)** — `lsp_typescript_diagnostic_sequence`'s pull-path producer, `logTypeScriptPullSettle`, put time-since-`didOpen` in the top-level `durationMs` field instead of the settle operation's own time, so a session's latency percentiles for this phase read document lifetimes as operation costs (147/239 records showed >60s "durations" for settles that took milliseconds). It also hardcoded `version: null` on every pull settle while the push path already logs real versions, making every pull settle look "unbound" to the staleness forensics this repo runs. `durationMs` now measures from the pull request to its `found`/`clean` resolution; document age keeps its own honest name, `metadata.elapsedSinceDidOpenMs`. `version` reads the real tracked value from `diagnosticsVersionsByPath`, falling back to the explicit `"pull-unversioned"` marker only when nothing has been stored yet — never a bare `null`. The same phase was also double-emitting: `ensureWarmForSweep`'s warm-up-only readiness probe and a sweep's real content-collecting touch both run a genuine pull round trip for the same file, often milliseconds apart, and both logged identically as `settleSource: "pull"` (239 records against 145 touches in the session evidence). The warm-up settle now tags `settleSource: "pull-warmup"` so the two legitimate observations are distinguishable instead of reading as duplicates.
  - `clients/lsp/client.ts` — `logTypeScriptPullSettle` takes the settle's own `durationMs` and a `pullSettleSource`; `clientWaitForDiagnostics` times the pull attempt and threads a `pullSettleSource` option through its three settle call sites; `version` reads `diagnosticsVersionsByPath` with a `"pull-unversioned"` fallback.
  - `clients/lsp/index.ts` — `touchFile`'s per-server wait tags `pullSettleSource: "pull-warmup"` when the touch's `source` is `"lsp_sweep_warmup"`.
  - Checked `scripts/analyze-pi-lens-logs.mjs` for consumers of the old `durationMs`/`version: null` semantics on this phase: none exist today, so nothing else needed updating.
