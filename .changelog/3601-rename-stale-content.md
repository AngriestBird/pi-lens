section: Fixed
---

- **`lsp_navigation`'s `rename` no longer rewrites a file that changed after the language server computed the rename (closes #3601)** — the tool applied the server's workspace edit with no expected-content check, so a concurrent `edit` or `write` to any file the rename touched was overwritten at the server's stale offsets. The rename's own file is now held to the bytes the tool sent the server, and every other file the edit writes text to that the language client has open is held to the bytes it last sent for it: the edit is refused, before any write, when a file's content differs from what the server computed against, naming the file in the tool result and counting one `lsp-edit-stale-content` degradation. A file the language client has not opened (the server reads it from disk) is refused only when it was written at or after the moment the rename was requested, less a 2 s margin for filesystem timestamp granularity, so a cross-file rename over unopened files still applies; a file the edit creates is not checked.
